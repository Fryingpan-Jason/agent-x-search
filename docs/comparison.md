# Why another X search MCP?

This is a focused option, not a claim that existing projects are bad or slower. Source descriptions checked on 2026-09-06; no comparative upstream benchmark was performed.

| Project | Documented focus | Distinction here |
| --- | --- | --- |
| [ponzu07/grok-x-search-mcp](https://github.com/ponzu07/grok-x-search-mcp) | Responses X/web search, package launch, its own OAuth login tools | Existing official CLI login reuse; no second token store; one default tool |
| [anlostsheep/grokodex](https://github.com/anlostsheep/grokodex) | Local Grok integration for coding, images and X search | Focused search package; CLI research optional, direct Responses is default |
| [zekaizer/grok-mcp](https://github.com/zekaizer/grok-mcp) | Responses research/X search with binary distribution | Node ESM package and six configuration outputs; different installation tradeoff |
| [xdevplatform/xMCP](https://github.com/xdevplatform/xMCP) | X API MCP | Different data/API and credential surface; not a like-for-like native Grok search wrapper |

What we can substantiate: no runtime dependencies, one default tool, explicit billing modes, and a local single-request direct path. What we cannot claim from this work: faster xAI inference, more complete X coverage, guaranteed account eligibility, lower total bills for every query, or universal client compatibility. Performance methodology and verification levels are published separately.
